# Справочник: команды madarch

Факты, на которые опираются страницы вики о том, как начать. Источник — вывод `madarch --help` и руководство «Start a product from the repositories you already have» в репозитории madarch (`docs/guides/start-a-product.md`).

## Установка {#install}

madarch ставится через npm (нужен Node.js 18 и новее): `npx madarch new`. На macOS есть Homebrew: `brew install shady2k/tap/madarch`. На Linux и macOS есть установочный скрипт, на Windows x64 — `install.ps1`; Windows arm64 не поддерживается. Для работы нужны git и настроенные `user.name` и `user.email`: madarch не меняет вашу git-личность.

## madarch init {#cmd-init}

Запускается в папке git-репозитория с вашим кодом. Создаёт отдельный продукт в домашней папке продуктов, подключает репозиторий ссылкой, не перемещая его, делает коммит репозитория продукта и открывает его вики. Берёт имя папки репозитория и адрес его `origin`, если он есть. Код остаётся там, где вы с ним работаете. Вне git используйте `madarch new`.

## madarch new {#cmd-new}

Создаёт черновик продукта — отдельный git-репозиторий — в домашней папке продуктов и открывает его вики. Папка черновика называется по дню создания: `idea-2026-10-11`, для второго черновика того же дня — `idea-2026-10-11-2`. Первый коммит пишет сама команда.

## madarch serve {#cmd-serve}

Открывает вики уже существующего продукта: папки из `--product` или папки, в которой запущена команда. Вики обслуживается на порту 4180; другой порт задаёт `--port`, а `--no-open` не открывает браузер.

## madarch start, stop и status {#cmd-server}

`madarch start` запускает один фоновый сервер для всех продуктов домашней папки, `madarch stop` его останавливает, `madarch status` показывает адрес, номер процесса, время работы и продукты. Сервер читает домашнюю папку заново, поэтому продукт, созданный после запуска, появляется без перезапуска.

## Домашняя папка продуктов {#products-home}

Домашняя папка продуктов — `~/madarch/products`. Её переносят переменной `MADARCH_HOME` (тогда продукты лежат в `products` внутри неё) или ключом `--home` для одной команды. `madarch list` называет продукты, которые она содержит: папку, идентификатор и имя каждого.

## madarch repo add {#cmd-repo-add}

Записывает в манифест продукта один репозиторий с кодом (имя, адрес и, по желанию, ветку) и подключает его в `repos/<имя>`. Без локальной копии клонирует адрес. С локальной копией спрашивает: связать (по умолчанию), переместить или клонировать. Связать — оставить копию на месте; переместить — перенести ветку, незакоммиченную работу и stash; клонировать — не трогать копию.

## madarch clone и bootstrap {#cmd-clone}

`madarch clone <адрес>` клонирует опубликованный репозиторий продукта в домашнюю папку и подтягивает его код: так присоединяется второй инженер. `madarch bootstrap` клонирует в `repos/<имя>` то, что объявляет манифест.

## madarch fill-stages {#cmd-fill-stages}

Запускает восемь детерминированных стадий заполнения — без агента — и печатает, сколько единиц работы запланировано и выполнено и какие факты теперь в графе по видам. Агента для вики запускает кнопка в самой вики, не эта команда.
